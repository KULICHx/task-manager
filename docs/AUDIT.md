## Исправлено

- Совместимость зависимостей Spring Boot 4 и автоконфигурации Kafka.
- Раздельные конфигурации API и consumer; запуск Kafka, Redis и двух PostgreSQL через Docker Compose.
- Контракт события с UUID; отправка после коммита БД; события удаления задач; Consumer с идемпотентной записью в аудит.
- Логика стратегии `URGENT`, ранее сбрасывавшая статус выполнения задачи.
- Redis: синхронизация записи и инвалидации с коммитом; сброс кэша задач при изменении пользователя или категории.
- API: единые ответы `{"error": "..."}` для типовых ошибок валидации, неверного JSON/enum, отсутствующих параметров и нарушений уникальности.
- GitHub Actions: проверка Maven и сквозной smoke test.
- Интеграционные тесты Consumer с PostgreSQL Testcontainers: идемпотентность, независимые события одной задачи, ошибка записи.
- Интеграционные тесты API: публикация Kafka-событий после коммита и отсутствие публикации при откате транзакции.

## Оставшиеся задачи

### Приоритет 1 — надёжность и корректность

1. **Гарантии Kafka.** При отказе брокера после коммита БД событие может потеряться. Для гарантированной доставки проработать transactional outbox, повторные попытки и обработку ошибок.
2. **Проверки отказов.** Базовые сценарии отката транзакции и повторной обработки события теперь покрыты тестами; дополнительно проверить недоступность Redis/Kafka и восстановление после сбоя.
3. **Контракт событий.** Версионировать формат `TaskEvent` и договориться о хранении времени с часовым поясом (например, `Instant` / UTC). Пока модели в API и consumer дублируются.
4. **Обработка ошибок.** Для дополнительных краевых случаев HTTP-запросов и доступа к данным продолжить унификацию ответов; базовые 400/404/409 уже покрыты.

### Приоритет 2 — развитие

1. **Безопасность:** добавить аутентификацию и разграничение доступа, если API будет доступен вне локального окружения.
2. **Производительность:** использовать пагинацию для больших выдач, проверить индексы и сложные фильтры.
3. **Стиль кода:** постепенно привести импорты и форматирование к `.editorconfig`, заменить шаблонные пакеты `org.example` при следующем рефакторинге; автоматический style gate пока не включён.
4. **Наблюдаемость:** проверить Prometheus/Logstash или удалить неиспользуемые экспериментальные файлы.

## Граница готовности для портфолио

Основная функциональность, сборка, локальная инфраструктура, Kafka-поток и текущие тесты **подтверждены**. Репозиторий пригоден как демонстрация backend-навыков для стажировки. Он **не заявляется production-ready** и не должен разворачиваться в интернет без дополнительных мер защиты.
