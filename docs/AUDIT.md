# Аудит Task Manager — 2026-11-08

Первоначально проведён статический аудит. **8 ноября 2026 года** GitHub Actions подтвердил Maven-сборку обоих сервисов, 30 тестов, запуск Docker Compose, миграции Liquibase и полный сценарий API → Kafka → Consumer → PostgreSQL-аудит. Проверка на Windows с JDK 21 и Docker Desktop ещё не проведена.

## Состояние проекта

- `api/`: REST API для пользователей, категорий и задач; Spring Boot 4.0.3, Java 21, JPA, Liquibase, Redis, Kafka producer, OpenAPI, тесты.
- `consumer/`: Kafka listener с PostgreSQL-аудитом и идемпотентной вставкой по `event_id`; Spring Boot 4.0.3, Java 21, JDBC, Liquibase, тест.
- `compose.yaml`: PostgreSQL (две БД), Redis и Kafka (KRaft) — **запуск проверен в Linux CI**, ручная проверка на Windows ожидается.
- `.env.example`: только тестовые значения для локального окружения; реальные локальные `.env` файлы игнорируются Git.

## План проверки и исправлений, по приоритетам

| Приоритет | Область | Факт / риск | Условие завершения |
|---|---|---|---|
| P0 | Build | В среде аудита нет Maven и недоступна загрузка дистрибутива; текущая сборка не подтверждена | `api` и `consumer` выполняют `mvnw clean test` |
| P0 | Infrastructure | Исходный Compose не запускал отдельную БД consumer и имел некорректную конфигурацию Kafka для взаимодействия из контейнеров | Оба PostgreSQL, Redis и Kafka доступны из приложений; топик создан |
| P0 | End-to-end | Нет подтверждённого сквозного сценария создания/изменения/удаления задач и записи трёх событий consumer | REST API отдаёт ожидаемые ответы; аудит содержит три события |
| P1 | Events | `@TransactionalEventListener(AFTER_COMMIT)` не гарантирует доставку: при недоступном Kafka сообщения теряются после коммита | Определить требования к надёжности; при необходимости реализовать transactional outbox и повторные попытки |
| P1 | Cache | `@CachePut`/`@CacheEvict` выполняются не обязательно после успешного DB commit | Тестом подтвердить согласованность данных при успешном коммите и откате; затем исправить |
| P1 | Integration tests | Интеграционный тест API использует PostgreSQL Testcontainers, но отключает Redis/Kafka; Kafka consumer тестируется только с Mockito | Добавить отдельный Kafka end-to-end / integration test, без зависимости от внешнего локального брокера |
| P1 | Error handling | Обработка ошибок API неполная: некорректные enum и параметры могут возвращать отличающийся от обычного формат ошибки | Единый контракт ошибок, проверка HTTP 400/404/409 и валидации |
| P1 | Kafka contract | `TaskEvent` дублируется в двух сервисах, а дата события без часового пояса | Тест совместимости сериализации, документированная схема и использование UTC/Instant при следующем изменении контракта |
| P2 | API scalability | Есть `GET /api/tasks` и фильтры без пагинации; при большом количестве задач будут грузиться все записи | Решить, нужны ли ограничения и Pageable во всех списках |
| P2 | Security | REST API без аутентификации, по умолчанию рассчитан на локальную демонстрацию | Не публиковать API в интернет без отдельного решения о доступе |
| P2 | Observability | Есть конфигурации Prometheus и Logstash, но они ещё не проверены и не включены в базовый Compose | Вынести в отдельный opt-in профиль и протестировать либо удалить неиспользуемое |
| P2 | Code quality | Пакет `org.example`, универсальные статические Mapper-классы, стилистические различия между файлами | После стабилизации привести стиль к единому и включить автоматическую проверку |
| P2 | Documentation | Полноценный README, API examples и архитектурная схема отсутствуют | Оформить после подтверждённого запуска |
| P2 | CI | GitHub Actions отсутствует | Проверка сборки и тестов на push / pull request |

## Проверки P0 — GitHub Actions

- **Maven:** [29 тестов API и 1 тест Consumer](https://github.com/KULICHx/task-manager/actions/workflows/ci.yml) прошли без ошибок.
- **Инфраструктура:** [full-stack smoke](https://github.com/KULICHx/task-manager/actions/workflows/smoke.yml) запускает PostgreSQL (API и аудит), Redis и Kafka; все контейнеры прошли healthcheck.
- **Сквозной сценарий:** HTTP создаёт пользователя, категорию и задачу, обновляет и удаляет задачу; consumer записывает в PostgreSQL три события (`TASK_CREATED`, `TASK_UPDATED`, `TASK_DELETED`).
- **Исправление по результатам первого падения:** в Spring Boot 4 вместо прямой зависимости `spring-kafka` используется `spring-boot-starter-kafka`, чтобы включить автоконфигурацию Kafka.

**Пока не проверено:** запуск на пользовательском Windows и восстановление после отказов брокера.
